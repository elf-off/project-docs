# Режим planning: еженедельные планы менеджеров

`app/services/planning_service.py` — обработка сообщений с маркером `#Планирование` в групповых чатах.

## Сценарий использования

Каждую неделю (до дедлайна — по умолчанию пятница 20:00 МСК) руководитель публикует в рабочий чат план роста по проектам:

```
#Планирование
М.Видео Чехов +10%
ДЗМ и Соц.объекты +5%
Ламода грузчики, ПВЗ -3%
```

Бот парсит сообщение, матчит названия проектов с внешним справочником и сохраняет план в БД. По понедельникам подводит план-факт.

---

## Пайплайн обработки

### 1. Проверка feature-флага

`ctx.has_feature('weekly_planning')` — если флаг выключен, сообщение игнорируется.

### 2. Валидация формата

До обращения к AI проводится трёхступенчатая проверка:

**Шаг 1:** `#Планирование` должно быть в первой строке (регистронезависимо). Если маркер найден в середине текста — это обсуждение планирования, а не сам план.

**Шаг 2:** В сообщении должны быть строки с числами (помимо первой). Иначе — это инструкция или вопрос.

**Шаг 3:** Все строки с числами должны содержать `%`. Если хоть одна числовая строка без `%` — бот отвечает в чат с просьбой исправить формат и прикладывает пример.

### 3. Проверка дедлайна

`_is_before_deadline()` — проверяет, что текущее время (в настроенной таймзоне) не позже дедлайна текущей недели. Дедлайн настраивается в `chats.config`:
- `planning_deadline_day` (0=Пн, 4=Пт, по умолчанию 4)
- `planning_deadline_hour` (по умолчанию 20)
- `planning_deadline_minute` (по умолчанию 0)

После дедлайна сообщения игнорируются без уведомления.

### 4. Загрузка справочника

Из внешней БД `2_kadry_4` загружаются два справочника:
- `ref_projects_wa` — отдельные проекты (`id`, `name`, `is_active=1`)
- `ref_project_groups` — группы проектов (`id`, `name`, `title`, `is_active=1`)

Если БД недоступна — бот сообщает об ошибке в чат и не обрабатывает план.

### 5. AI-парсинг и матчинг

Claude получает полный текст сообщения + JSON-списки проектов и групп. Задача Claude:
- Извлечь все позиции с процентами
- Определить, проект это или группа
- Сопоставить с записями в справочнике (с учётом опечаток, регистра, сокращений, разбиения перечислений через запятую и `/`)
- Вернуть JSON с `entries` и `not_found`

Пример работы матчинга из промпта:
- `"ЯМ СЦ, ФФЦ Екатеринбург +10%"` → два проекта: "ЯМ СЦ Екатеринбург" и "ЯМ ФФЦ Екатеринбург", каждый +10%
- `"ДЗМ"` → группа "ДЗМ и Соц.объекты" из `ref_project_groups`

### 6. Обработка not_found

Если Claude не смог сопоставить некоторые названия — бот отвечает в чат:
```
Проекты не найдены в справочнике:
Неизвестный проект, Ещё один

Проверьте написание и отправьте план повторно.
```

Если `not_found` есть, но `entries` тоже есть — submission всё равно создаётся (частичный план).  
Если `entries` пуст (все в `not_found`) — submission не создаётся.

### 7. Сохранение

**Менеджер:** ищется в `planning_managers` по `(chat_id, tg_user_id)`. Если не найден — создаётся автоматически. Имя и username обновляются при каждой отправке (могут меняться в Telegram).

**Замена старых plans:** Если менеджер уже подавал план на эту же ISO-неделю — старые submission и entries удаляются (менеджер может корректировать план до дедлайна).

**Baseline:** При сохранении каждого entry сразу запрашивается факт за **прошлую** неделю (`exits_wa`) — это baseline для расчёта план-факта в понедельник.

## Определение целевой недели

Каждый план всегда на **следующую** ISO-неделю:
```python
next_week_date = now + timedelta(weeks=1)
plan_year, plan_week, _ = next_week_date.isocalendar()
```

## Plan-Fact отчёт (понедельник)

По понедельникам в `growth_check_hour:growth_check_minute` (по умолчанию 10:00 МСК) `TimerWorker` запускает `_check_growth_plan_fact()`.

**Алгоритм:**
1. Находит все принятые (`is_accepted=True`) и ещё непроверенные (`fact_checked_at IS NULL`) submissions за прошлую неделю.
2. Дедупликация: если менеджер подавал план несколько раз, берётся последний по `id`.
3. Для каждого entry:
   - Запрашивается факт за целевую неделю (`exits_wa`)
   - **Пересчитывается baseline** за неделю до целевой (вдруг при подаче плана неделя была неполной)
   - Вычисляется `fact_growth_percent = (fact - baseline) / baseline * 100`
   - Статус: `achieved` (факт >= плана), `partial` (факт >= план - 10%), `missed` (иначе), `no_data`
4. Формируется единый сводный HTML-отчёт для **всех** менеджеров.
5. Отправляется в `GROWTH_REPORT_CHAT_ID` (чат руководства).
6. Все submissions помечаются как проверенные.
7. В `growth_reports` сохраняется лог.

**Пример отчёта:**
```
Сводный план-факт за неделю 10.03-16.03.2026

--- @ivanov ---
  М.Видео Чехов: +10% → +12.5% (80→90)
  ДЗМ: +5% → +2.1% (200→204)
Итого: 1/2 (50%)

--- @petrov ---
  Ламода ПВЗ: -3% → -5.2% (100→95)
Итого: 0/1 (0%)

ИТОГО: 1 из 3 выполнено (33%)
```
