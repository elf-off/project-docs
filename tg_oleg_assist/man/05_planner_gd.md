# Режим assist: дневной планёр ГД

`app/services/planner/planner_service.py` — личный чат с генеральным директором.

## Смысл

Бот структурирует рабочий день ГД: утром показывает повестку, днём и вечером запрашивает обратную связь по выполненным блокам. По итогу Claude анализирует ответы и даёт рекомендации.

## Расписание (по умолчанию, МСК)

| Время | Действие |
|---|---|
| 09:00 | Информационное сообщение с повесткой дня (БЕЗ кнопок) |
| 14:00 | Запрос обратной связи по утренним блокам (10:00–14:00) с кнопками |
| 20:30 | Запрос обратной связи по вечерним блокам (15:00–19:00) с кнопками |
| 21:30 | Автозакрытие незавершённых циклов |

Расписание конфигурируется через `chats.config` (`planner_morning_info_hour`, `planner_feedback_morning_hour` и т.д.). Работает только в рабочие дни (Пн–Пт).

## Структура данных

Для каждого цикла обратной связи (half='morning' или half='afternoon') в таблице `planner_states` хранится FSM-состояние. Уникальный ключ — `(user_id, half)`. Это позволяет двум циклам существовать одновременно.

Завершённые сессии сохраняются в `planner_feedbacks`.

## Повестка дня (09:00)

`send_morning_info()` — отправляет информационное сообщение с темой дня и перечнем всех временных блоков. Кнопок нет. State не создаётся. Это просто справочное сообщение.

Темы по дням недели описаны в `planner_day_themes.py` (`DAY_THEMES`): понедельник — стратегия и планирование, вторник — операционные процессы и т.д.

## Запрос обратной связи (14:00 и 20:30)

`send_feedback_request(half)` — отправляет сообщение с вопросом "как прошли блоки?" и тремя inline-кнопками:

- **Выполнено** (`planner_completed`)
- **Частично** (`planner_partial`)
- **Не удалось** (`planner_failed`)

Одновременно создаётся `PlannerState` со статусом `AWAITING_STATUS` для данного half.

## FSM обработки обратной связи

### Нажатие кнопки (callback_query)

`handle_callback(user_id, callback_data)` — только ГД (проверяется `planner_ceo_user_id` из `chats.config`) может нажимать кнопки.

Определяется активный half: проверяются оба state (morning, afternoon), берётся первый в статусе `AWAITING_STATUS`.

- **Частично / Не удалось** → feedback сохраняется сразу, state удаляется, бот подтверждает.
- **Выполнено** → state переводится в `AWAITING_QUALITY`, бот спрашивает оценку качества.

### Текстовые ответы (handle_text_message)

После нажатия "Выполнено" ГД отвечает на серию вопросов в личке:

```
AWAITING_QUALITY   -> оценка 1-10 (число, иначе повторить вопрос)
    |
AWAITING_WORKED    -> что сработало (свободный текст)
    |
AWAITING_TO_ADD    -> что добавить в следующий раз
    |
AWAITING_PROBLEM   -> главная проблема (можно пропустить: "нет", "skip", "пропустить")
    |
AWAITING_DECISION  -> принятое решение (можно пропустить)
    |
    --> сохранить PlannerFeedback, удалить state
    --> _run_analysis()
```

State имеет TTL до 21:30 того же дня. Если TTL истёк — state удаляется, текстовый ответ игнорируется.

### Автозакрытие (21:30)

`end_of_day()` — закрывает оба незавершённых цикла (morning и afternoon). Сохраняет feedback с накопленными данными (что успело ответить ГД) и статусом `NO_RESPONSE` для незаполненных полей. Отправляет сообщение об автозакрытии.

## Анализ через Claude (_run_analysis)

После завершения FSM вызывается анализ:

1. **Загрузка метрик** — best effort запрос к `2_kadry_4.exits_wa` для получения данных по плановым и фактическим выходам за текущую неделю. Если БД недоступна — анализ проводится без метрик.

2. **Формирование запроса** — `build_user_message()` собирает контекст: дата, тема дня, статус выполнения, оценка, ответы на вопросы, метрики (если есть).

3. **Запрос к Claude** — `temperature=0.3`, `max_tokens=4096`. Claude возвращает JSON с анализом и рекомендациями.

4. **Сохранение лога** — `PlannerAnalysisLog` с сырым запросом, ответом и latency_ms.

5. **Отправка результата** — форматированное HTML-сообщение в личный чат ГД.

При ошибке API отправляется стандартное сообщение об ошибке (`format_analysis_error()`).

## Вспомогательные модули

- `planner_formatter.py` — форматирование всех типов сообщений (утренняя повестка, запросы, подтверждения, результат анализа)
- `planner_prompts.py` — системный промпт (`PLANNER_SYSTEM_PROMPT`) и `build_user_message()`
- `planner_day_themes.py` — темы и блоки каждого дня недели, константы (`CALLBACK_STATUS_MAP`, `SKIP_WORDS`, `PlannerStep`, `MeetingStatus`, `DayOfWeek`)
