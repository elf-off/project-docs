# ЗАДАЧА: Исправить ложную деактивацию вакансий при синке

## Контекст

Проект: `/opt/openai/crm-worker/`
Ветка: `main`

## Проблема

`services/vacancy_sync.py` строка ~286-293: после синка вакансий с Avito API, код помечает `is_active=False` все вакансии аккаунта, которых нет в полученном списке.

**Результат:** Все 35 вакансий Avito 8к2 стали `is_active=0`, хотя они реально существуют на Avito. Причина — API возвращает вакансии постранично или с лимитом, и не все попадают в один ответ.

## Решение

### Вариант А (безопасный) — убрать автодеактивацию

Закомментировать или удалить блок на строках ~286-293, который делает:

```python
# 3. Пометить вакансии, которых нет в списке, как is_active=False
...
.values(is_active=False)
```

Вакансии будут деактивироваться только если Avito API вернёт явный статус "закрыта/удалена" в данных вакансии.

### Вариант Б (умный) — деактивировать только если собрали ВСЕ вакансии

Деактивировать только если:
1. API вернул полный список (нет следующей страницы / `has_more=false`)
2. И вакансия не встречалась в ПОЛНОМ списке

```python
# Деактивировать только если мы точно получили ВСЕ вакансии аккаунта
if not has_more_pages:
    # Теперь безопасно пометить отсутствующие как неактивные
    ...
```

### Рекомендация: Вариант А

Для нашего случая безопаснее просто не деактивировать автоматически. Вакансии, которые реально закрыты на Avito, будут помечены при следующем ручном аудите или по отдельному API-вызову.

## Порядок работы

1. Прочитай `services/vacancy_sync.py` целиком — пойми как работает синк
2. Найди блок деактивации (~строки 286-293)
3. Закомментируй или удали его
4. Добавь лог-сообщение: `log.info("vacancy_deactivation_skipped", reason="disabled_for_safety")`

## Проверка

1. Перезапустить сервис
2. Подождать 30 мин (или дождаться синка)
3. Проверить: `SELECT is_active, COUNT(*) FROM vacancies WHERE account_id=3 GROUP BY is_active;`
4. Все вакансии должны остаться `is_active=1`
