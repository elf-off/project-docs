# Deploy: Эмулятор отклика для тестирования AI-бота

**Дата:** 2026-03-19

## Что сделано

Добавлен механизм эмуляции откликов для тестирования AI-бота без реальных кандидатов с Авито. Включает admin-эндпоинты для создания тестовых откликов, отправки сообщений "от кандидата" и просмотра диалога, а также UI-секцию "Тестирование" в админке.

### Изменения

| Файл | Что изменено |
|------|-------------|
| `services/avito_messenger.py` | Перехват отправки для тестовых чатов (`test-chat-*`) -- сообщения сохраняются в БД, но не уходят в Авито |
| `api/admin.py` | 4 новых эндпоинта: `emulate-application`, `emulate-message`, `test/dialog`, `test/vacancies` |
| `workers/incoming_processor.py` | Тестовые чаты пропускают проверки `ai_enabled` и `is_night_window` |
| `templates/admin.html` | Секция "Тестирование" с формой эмуляции и просмотром диалога |

### Новые API-эндпоинты

| Метод | URL | Описание |
|-------|-----|----------|
| POST | `/admin/api/test/emulate-application` | Создает тестовый отклик и запускает AI-flow |
| POST | `/admin/api/test/emulate-message` | Отправляет сообщение "от кандидата" в тестовый чат |
| GET | `/admin/api/test/dialog/{chat_id}` | Просмотр всех сообщений тестового диалога |
| GET | `/admin/api/test/vacancies?account_id=N` | Список вакансий аккаунта для выбора в форме |

## Порядок деплоя

Миграции не требуются. Только обновление кода.

### 1. Обновить код

```bash
cd /opt/crm-worker
git pull
```

### 2. Перезапустить сервис

```bash
sudo systemctl restart k24-crm-worker
```

### 3. Проверить

1. Открыть админку, перейти в раздел "Тестирование"
2. Выбрать аккаунт (с AI), нажать "Запустить эмуляцию"
3. Через 5-15 сек должен появиться greeting от AI
4. Отправить ответ "от кандидата" через поле ввода
5. Убедиться, что диалог продвигается по стадиям
6. Проверить что в логах Авито API нет запросов к тестовым чатам

## Сценарий тестирования

```
1. POST /admin/api/test/emulate-application
   {"account_id": 2, "candidate_name": "Иван Тестов", "candidate_phone": "+79998887766"}
   -- Создан application, chat, ai_session
   -- AI генерирует greeting (через 5-15 сек)

2. GET /admin/api/test/dialog/{chat_id}
   -- Видим greeting от AI

3. POST /admin/api/test/emulate-message
   {"chat_id": 789, "text": "Москва, метро Бауманская, 25 лет"}
   -- AI обрабатывает квалификацию, отправляет презентацию

4. POST /admin/api/test/emulate-message
   {"chat_id": 789, "text": "Да, интересно"}
   -- AI предлагает запись на звонок

5. POST /admin/api/test/emulate-message
   {"chat_id": 789, "text": "Завтра в 10 утра"}
   -- AI создает handover-карточку
```

## Как это работает

- Все тестовые ID начинаются с `test-` -- легко отличить от реальных
- Тестовые сообщения НЕ уходят в Авито -- перехватываются в `send_message` по префиксу `test-chat-`
- `force_night=True` по умолчанию -- не нужно ждать ночного окна
- `incoming_processor` пропускает проверки `ai_enabled` и `is_night_window` для тестовых чатов
- Scheduler (`process_scheduled`) обрабатывает тестовые сообщения так же как реальные, но отправка перехватится
- Тестовые данные остаются в БД -- для очистки можно добавить отдельный эндпоинт позже
